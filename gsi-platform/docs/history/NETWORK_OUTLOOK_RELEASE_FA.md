# اصلاحیه V27.1.1 — پوشه شبکه و Outlook

این نسخه بر مبنای فایل V27.1 ارسالی اصلاح شده است؛ وب‌سرور مشترک، API یا پایگاه داده سروری لازم ندارد. پردازش مرکزی روی یک رایانه سازمانی انجام می‌شود. کاربران HTML را از ایمیل یا پوشه مجاز می‌خوانند؛ برنامه شخصی در صورت نیاز فقط روی localhost اجرا می‌شود. هیچ ایمیلی طی بررسی ارسال نشده است.

## تغییرات قابل بررسی

- قفل قدیمی دیگر صرفاً بر اساس زمان حذف نمی‌شود؛ مالک قفل هنگام آزادسازی کنترل می‌شود.
- جایگزینی اتمیک فایل با حفظ نسخه قبلی در خطای نوشتن و تلاش مجدد محدود برای خطای دسترسی انجام می‌شود. فایل اصلی Excel پیش از جایگزینی حذف نمی‌شود.
- کلید شخصی اجازه انتشار Snapshot مرکزی از طریق برنامه را ندارد. schema، نوع فایل، هویت و سلامت SQLite هنگام خواندن بررسی می‌شوند.
- قطع دسترسی ریشه شبکه به‌عنوان داده خالی گزارش نمی‌شود. Snapshot و زمان انتشار در یک خواندن دریافت می‌شوند.
- کلیدهای UTF-8 BOM و UTF-16 تولیدشده در Windows قابل خواندن‌اند؛ Base64 نامعتبر رد می‌شود.
- فایل‌های موقت HTML نام یکتا دارند. عنوان گزارش دیگر وعده داده لحظه‌ای نمی‌دهد.
- فیلدهای واقعی NEXT_ACTION به خروجی منتقل می‌شوند؛ محدودیت ردیف و تنظیمات نامعتبر کنترل می‌شوند. fallback انتشار همه ستون‌های ناشناخته حذف شد.
- فهرست صریح کاربران، برای کاربر بدون رکورد Snapshot خالی منتشر می‌کند تا اطلاعات قبلی باقی نماند.
- نمای شخصی عنوان و حجم اقدام‌ها را با مخاطب تغییر می‌دهد؛ فیلتر بحرانی اعمال می‌شود. جزئیات فنی ذخیره‌سازی از متن مخاطب حذف شده‌اند. این تغییر نقش، سطح دسترسی را افزایش نمی‌دهد.
- گزارش روزانه علاوه بر Excel، HTML خودبسنده مناسب بازشدن در مرورگر پیوست می‌کند. نمودار تعاملی در بدنه Outlook اجرا نمی‌شود.
- انتخاب حساب فرستنده در ایمیل شخصی رعایت می‌شود؛ قبل از ارسال صریح، گیرندگان توسط Outlook Resolve می‌شوند.
- کش کشف مراحل بعد از تغییر فایل‌ها تازه می‌شود؛ آزمون شکست‌خورده نسخه پایه به این مسیر مربوط بود.

## استقرار پیشنهادی

۱. نسخه قبلی برنامه، کلید اصلی و پوشه کاربران را جداگانه پشتیبان بگیرید. کلید اصلی را عوض نکنید؛ داده قبلی با کلید جدید باز نمی‌شود.
۲. پوشه برنامه جدید را کامل جایگزین کنید؛ فایل‌های نسخه‌ها را با هم مخلوط نکنید. Python 3.11+ و وابستگی‌های requirements.txt لازم‌اند.
۳. فقط رایانه ناشر، GSI_PROFILE_KEY_FILE را به کلید اصلی خارج از Share و GSI_PROFILE_ROOT را به مسیر UNC واقعی متصل کند. کاربران فقط کلید شخصی خود را داشته باشند.
۴. دسترسی NTFS و Share: ناشر روی Snapshotها حق نوشتن؛ هر کاربر روی Snapshot خودش فقط خواندن و روی state خودش خواندن/نوشتن؛ کاربران دیگر هیچ دسترسی. این ACL را مدیر شبکه اعمال کند؛ رمزگذاری جای ACL نیست.
۵. یک ناشر فعال داشته باشید؛ اجرای هم‌زمان دو انتشار مرکزی پشتیبانی نشده و ممکن است اجرای قدیمی‌تر دیرتر پایان یابد. Task Scheduler باید اجرای هم‌پوشان را منع کند.
۶. برای پاک‌شدن پرونده‌های واگذارشده قبلی، فهرست کامل کاربران همین انتشار را صریح بدهید:

```powershell
python -m gsi publish-personal --employees 1001,1002,1003
```

بدون این فهرست، کاربران غایب در ورودی دست‌نخورده می‌مانند. فقط پس از تأیید کامل‌بودن ورودی، انتشار را انجام دهید؛ ورودی ناقص با «کاربر بدون پرونده» یکسان نیست.

۷. نصب هر کاربر با فایل کلید امن خارج از Share:

```powershell
python tools\windows\install_gsi_personal_protocol.py --employee 1001 --root "\\server\share\GSI\Users" --user-key-file "C:\Secure\user1001.key"
python -m gsi personal-open
python -m gsi personal-html --employee 1001 --output "C:\Reports\Personal.html"
```

نصاب قبل از تغییرات کلید را اعتبارسنجی می‌کند. اگر محدودکردن ACL شکست بخورد نصب متوقف می‌شود؛ نصاب تراکنش کامل فایل‌ها و Registry ندارد. در نصب ناموفق اجرا را شروع نکنید؛ تنظیمات قبلی را بازیابی یا نصب را کامل کنید.

برای گزارش روزانه ابتدا `python -m gsi email --help` را ببینید و پیش‌نویس را کنترل کنید. ارسال واقعی فقط با انتخاب صریح ارسال انجام شود. اتوماسیون COM نیازمند Classic Outlook روی Windows و حساب سازمانی پیکربندی‌شده است؛ دریافت موفق ایمیل با برگشت Send اثبات نمی‌شود.

## بازیابی و آزمون سازمانی

- قطع Share: کاربر باید پیام خطا بگیرد، نه گزارش خالی موفق. فایل قبلی HTML ممکن است هنوز روی دیسک باشد؛ تاریخ انتشار آن ملاک است.
- قفل باقی‌مانده: ابتدا توقف همه نویسندگان را تأیید کنید؛ سپس مدیر فقط فایل `.lock` مربوط را حذف کند. حذف خودکار زمان‌محور عمداً وجود ندارد.
- دو نشست از یک کاربر، ذخیره تنظیمات، قطع شبکه هنگام نوشتن و بازشدن مجدد گزارش را روی Share آزمایشی بسنجید.
- گیرنده، حساب فرستنده، RTL، جدول‌ها، پیوست HTML و لینک gsi:// را در Outlook واقعی بررسی کنید. اگر سیاست سازمان لینک یا پیوست را مسدود کرد، اجرای `python -m gsi personal-open` یا فایل HTML از پوشه مجاز مسیر جایگزین است.
- HTML و کش محلی آن رمزگذاری‌شده نیستند؛ آن‌ها را فقط در پروفایل و پوشه مجاز کاربر نگه دارید. بازکردن پیوست، ارتباط زنده با ناشر ایجاد نمی‌کند.

## نتیجه و حدود اعتبار

آزمون‌های جدید خطای ذخیره‌سازی، قفل، جداسازی کلید، خرابی ساختار، پاک‌شدن Scope خالی، داده غیرمتناهی و تنظیمات را با تزریق خطا روی فایل‌سیستم محلی می‌سنجند. لاگ کامل آزمون همراه بسته است. آزمون COM واقعی، SMB سازمانی، نصب Registry و بازبینی تصویری Outlook در این محیط انجام نشده است.

نمای شخصی هنوز تبدیل تقویم شمسی برای موعدها ندارد؛ تاریخ با قالب منبع نمایش داده می‌شود و این موضوع در گزارش نوشته شده است. تنظیم انتخاب ویجت و نمودار در HTML شخصی هنوز کامل نیست. فرم Word، تحلیل کامل واریانت فرایند و بازطراحی بر مبنای Figma در این اصلاحیه انجام نشده‌اند. این بسته اصلاحیه دیباگ است، نه تأیید صفرخطابودن کل سامانه یا تأیید تطابق با Figma.

نتیجه اجرای نهایی: **۷۶۷ آزمون موفق، صفر شکست**. بررسی نحوی کد و آزمون ادعاهای مستندات نیز انجام شد.
