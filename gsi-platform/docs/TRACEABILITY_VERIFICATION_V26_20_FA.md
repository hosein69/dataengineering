# صحت‌سنجی قابلیت رهگیری V26.20 — از صف تخصیص تا رفع تعهد

**تاریخ مرجع:** ۱۴۰۵/۰۶/۲۶ (2026-09-17)  
**محصول:** GSI | Global Sourcing Intelligence

## جمع‌بندی اجرایی
از نظر معماری، GSI اکنون می‌تواند زنجیره `صف تخصیص → تخصیص → خرید ارز → تأمین وجه → SWIFT/تبدیل → حمل → ورود گمرکی → ترخیص فیزیکی → ارائه/تطبیق سند گمرکی نزد بانک → رفع تعهد` را در یک Case Ledger نگه دارد. اما «کامل بودن رهگیری» برای هر پرونده مشروط به وجود Evidence از سورس متناظر است. سیستم نباید جای داده گمشده، Event یا تاریخ بسازد.

## ماتریس رهگیری
| مرحله | Evidence مورد انتظار | وضعیت فنی V26.20 | نکته کنترلی |
|---|---|---|---|
| صف تخصیص | NTSW request row/date/status | قابل رهگیری Request-level | رتبه فقط اگر export بدهد |
| تخصیص | NTSW allocated request/amount/date | قابل رهگیری | history dedupe می‌شود |
| خرید ارز | FX transaction / bank evidence | قابل رهگیری | Allocation ≠ FX Purchase |
| تأمین وجه | finance/bank funding evidence | قابل رهگیری | FX Purchase ≠ Funding |
| SWIFT/پرداخت | SWIFT/payment evidence | قابل رهگیری | Funding ≠ Supplier Payment |
| تبدیل ارز | source/target currency + cross rate + fee | قابل رهگیری مشروط | نبود evidence ⇒ P&L ساخته نمی‌شود |
| حمل | BL/shipment evidence | قابل رهگیری | BL به‌عنوان payment key استفاده نمی‌شود |
| ورود گمرکی | customs/cotage evidence | قابل رهگیری | ورود ≠ ترخیص |
| ترخیص فیزیکی | clearance evidence | قابل رهگیری | ترخیص ≠ ارائه سند به بانک |
| سند ترخیص نزد بانک | document submission/matching evidence | مستقل | SATA/Cotage جانشین تاریخ بانک نمی‌شود |
| رفع تعهد | NTSW/bank obligation evidence | قابل رهگیری | تعهد سند، مابه‌التفاوت و وثیقه مستقل‌اند |

## نکات مقرراتی که در طراحی اثر داده‌اند
1. مقررات جاری بانک مرکزی تعهد مربوط به «ارائه سند ترخیص مطابق» را از تعهد مربوط به «پرداخت مابه‌التفاوت نرخ ارز» تفکیک کرده و آزادسازی وثایق را نیز به ایفای تعهد مربوط می‌کند. بنابراین یک Boolean ساده «رفع تعهد شد» مدل کافی نیست.
2. بخش هفتم مجموعه مقررات ارزی همچنان محور بررسی سند/پروانه گمرکی و تطابق آن با ثبت سفارش و اسناد حمل است؛ GSI این Evidence را مستقل از خروج فیزیکی کالا نگه می‌دارد.
3. اطلاعیه‌های ۱۴۰۵ سامانه جامع تجارت نشان می‌دهند پرونده «در صف تخصیص» می‌تواند تحت شرایط خاصِ ویرایش/تمدید قرار گیرد؛ پس Queue یک Stage واقعی و تاریخ‌دار است، نه صرفاً برچسب.
4. مسیر معاملات مستقیم و غیرمستقیم مرکز مبادله در ۱۴۰۵ تفکیک شده؛ Route باید attribute خود Allocation باشد.
5. گمرک در ۱۴۰۵ امکان ترخیص بدون SATA را با شرط ثبت تعهد عدم درخواست ارز پس از ترخیص اعلام کرده است. بنابراین `SATA missing` به‌تنهایی Compliance Violation نیست و eligibility/evidence لازم است.
6. تمدیدهای اضطراری ۱۴۰۵ باید eligibility-driven باشند. سیستم Rule را blanket روی همه پرونده‌ها اعمال نمی‌کند.
