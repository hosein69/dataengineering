# HRPerf 1.2.0 — گیرندگان ایمیل از جدول پرسنلی

## چه چیزی عوض شد

فهرست گیرندگان بسته ایمیل می‌تواند از **ستون ایمیل جدول پرسنلی همان
اجرا** خوانده شود، نه از یک فهرست دستیِ جداگانه.

## چرا

جدول پرسنلی (`run.people`) همان چیزی است که امتیازها از آن ساخته شده‌اند.
گرفتن گیرنده از همان جدول یعنی گزارش و فهرست گیرنده **هرگز از هم جدا
نمی‌افتند**: اگر کسی در این اجرا امتیاز دارد، وضعیت پرسنلی‌اش همان است که
برای ایمیل هم به‌کار می‌رود. فهرست دستی این تضمین را ندارد و به‌مرور با
واقعیت فاصله می‌گیرد.

## فعال‌سازی

```bash
export HRP_EMAIL_FROM_HR=1
python -m hrperf run --formats excel,html,pdf,email
```

| متغیر | پیش‌فرض | کار |
|---|---|---|
| `HRP_EMAIL_FROM_HR=1` | خاموش | فعال‌سازی |
| `HRP_EMAIL_HR_ROLES` | `مدیر,رئیس,مسئول` | فیلتر `role` |
| `HRP_EMAIL_HR_MANAGEMENTS` | — | فیلتر `management` |
| `HRP_EMAIL_HR_DEPARTMENTS` | — | فیلتر `department` |
| `HRP_EMAIL_HR_MAX` | — | سقف تعداد |

ستون ایمیل با چند نام شناخته می‌شود: `email` · `Email` · `EMAIL` ·
`hr_email` · `HR_EMAIL` · `ایمیل` · `پست الکترونیک(ی)` — پس همان جدولی
که از سورس AIBL می‌آید هم بدون نگاشت دستی کار می‌کند.

## ترتیب حل گیرنده

```
۱) HRP_EMAIL_TO
۲) HRP_RECIPIENTS_FILE
۳) $HRP_HOME/recipients.yaml
۴) جدول پرسنلی اجرا  (فقط اگر HRP_EMAIL_FROM_HR روشن باشد)
۵) خالی ⇒ ساخت گزارش کار می‌کند، ارسال با خطای صریح متوقف می‌شود
```

## در خروجی گزارش

`ReportResult.email_recipients` تعداد گیرندگان حل‌شده را نگه می‌دارد و در
پیام‌های ساخت گزارش هم می‌آید («گیرندگان: ۱۲»). **فقط تعداد** — نشانی‌ها
نه در پیام‌ها می‌آیند نه در لاگ.

## تصمیم‌های محافظه‌کارانه

همان قواعد پلتفرم AIBL: پیش‌فرضِ فقط سطوح مدیریتی، فقط پرسنل فعال،
اعتبارسنجی شکل نشانی، خاموش به‌صورت پیش‌فرض، و لاگ‌نکردن نشانی‌ها.
