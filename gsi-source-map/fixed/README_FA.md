# GSI Source Profiler — نسخه بازبینی‌شده

از Sourceهای واقعی یک **Evidence Pack** می‌سازد تا مبنای شناخت grain، کلیدها، وضعیت‌ها و روابط باشد.
این نسخه drop-in است: همان CLI، همان نام فایل‌های خروجی، به‌علاوه `coverage_report.json`.

نقص‌های نسخه قبل و شاهد هرکدام در `../MAP_DEFECTS.md` است.

## نصب و اجرا

```bash
pip install pandas openpyxl pyyaml

export GSI_DATA_ROOT=/mnt/gsi/data        # ویندوز: set GSI_DATA_ROOT=D:\of\blstotal
python gsi_source_profiler.py --config gsi_sources.yaml --output gsi_evidence_pack --sample-rows 18
```

**کد خروج معنا دارد:**

| کد | یعنی |
|---|---|
| `0` | همه منابع پیکربندی‌شده پروفایل شدند |
| `2` | دست‌کم یک منبع هیچ شاهدی تولید نکرد — pack ناقص است |

برای اجرای عمدی روی زیرمجموعه‌ای از منابع: `--allow-missing`.

## خروجی

| فایل | محتوا |
|---|---|
| `executive_summary.md` | پوشش منابع، تعداد فریم، تعارض‌های کلید، نقش‌های قابل join |
| `model_context_pack.md` | سند اصلی برای مدل: پوشش، تعارض‌ها، و برای هر فریم grain/کلید/وضعیت/رابطه |
| `process_key_index.json` | نقشه نقش↔ستون بین منابع + `secondary_role_columns` |
| `coverage_report.json` | وضعیت هر منبع و فهرست خطاها، ماشین‌خوان |
| `source_catalog.json` | پروفایل کامل هر فریم |
| `schemas/*.json` | آمار ستونی، نقش، سمت (`header`/`po`/`pack`)، امتیاز کاندید کلید |
| `samples/*.csv` | ردیف‌های نمونه با `__excel_row__`, `__source_file__`, `__sheet__` |
| `run_manifest.json` | اندازه و SHA256 فایل‌هایی که **همین اجرا** نوشته است |

## قواعدی که ابزار رعایت می‌کند

**۱. سنجه هرگز کلید نیست.** ستونی که تاریخ، مبلغ، مقدار، ارز یا وضعیت دارد، هر طور که نامش نوشته شده باشد، نقش کلید نمی‌گیرد. `po.Net Order Value` و `Quantity In Order` دیگر کلید ORDER نمی‌شوند.

**۲. نقش خاص بر نقش عام مقدم است.** `شماره پرونده ثبت سفارش` نقش `REG_FILE` می‌گیرد نه `REG`؛ `Purchase order` نقش `PO` می‌گیرد نه `ORDER`؛ `po.Item of requisition` نقش `PR_ITEM` می‌گیرد نه `PO_ITEM`.

**۳. برای هر نقش، یک ستون نماینده.** انتخاب بر اساس پوشش و سپس یکتایی است، نه ترتیب ستون در اکسل. بقیه ستون‌های هم‌نقش در `secondary_role_columns` گزارش می‌شوند و عمداً وارد نقشه join نمی‌شوند.

**۴. تعارض هم‌نقش گزارش می‌شود، ادغام نمی‌شود.** اگر دو ستون یک نقش روی یک ردیف مقدار متفاوت داشته باشند — مثل `Purchase Requisition` هدر در برابر `po.Purchase Requisition` — به‌عنوان `key_conflicts` ثبت می‌شود. یکی‌گرفتن آن‌ها یک lineage می‌سازد که در هیچ ردیف منبعی وجود ندارد.

**۵. نرمال‌سازی فقط برای شمارش.** ی/ي، ک/ك، ه/ة، نیم‌فاصله، کشیده و ارقام فارسی برای مقایسه یکی می‌شوند تا یک وضعیت یک سطل بماند و یک کلید یک بار شمرده شود. **هر مقداری که در خروجی چاپ می‌شود، مقدار خام منبع است**؛ املاهای متفاوتی که روی هم افتاده‌اند در `raw_variants` دیده می‌شوند.

**۶. grain بدون پوشش اعلام نمی‌شود.** کاندیدی که روی کمتر از ۳۰٪ ردیف‌های فریم دیده شود گزارش می‌شود اما هرگز «بهترین» نامیده نمی‌شود.

**۷. شماره ردیف export کلید کسب‌وکاری نیست.** `ردیف` نقش `EXPORT_ROW_NO` می‌گیرد و نه grain تعریف می‌کند نه وارد نقشه join می‌شود. `شماره ردیف تعهد` و `ردیف درخواست` نقش `NATIVE_ROW_ID` می‌گیرند. بدون این تفکیک، یک ردیف تعهد تکراری پشت شمارنده‌ی export پنهان می‌ماند.

**۸. کلید مرکب تکراری سؤال می‌سازد، نه نتیجه.** وقتی یک grain مرکب تکرار شود، ابزار صریح می‌پرسد: رویداد کسب‌وکاری دوم، یا همان رکورد که در snapshot بعدی دوباره دیده شده؟ پاسخش با مالک منبع است.

**۹. co-observed رابطه معتبر نیست.** هر رابطه فیلد `assertion` دارد که همین را می‌گوید. اشتراک نام نقش بین دو منبع، آن دو شناسه را یک موجودیت نمی‌کند.

**۱۰. پوشش ناقص بلند اعلام می‌شود.** منبع مفقود یا ناموفق در بالای هر دو سند با بنر می‌آید، در `coverage_report.json` ثبت می‌شود و کد خروج را غیرصفر می‌کند.

## نقش‌ها

`PR` · `PR_ITEM` · `PO` · `PO_ITEM` · `ORDER` · `REG` · `REG_FILE` · `CUSTOMS_FILE` · `BL` · `COTTAGE` · `MATERIAL` · `SUPPLIER` · `WORKFLOW` · `COMPARISON` · `NATIVE_ROW_ID` · `EXPORT_ROW_NO`
سنجه‌ها: `DATE` · `STATUS` · `AMOUNT` · `QUANTITY` · `CURRENCY`

ستونی که هیچ نقشی نگیرد در `unclassified_columns` گزارش می‌شود — حدس زده نمی‌شود.

## منطق نمونه‌گیری

Sample تصادفی نیست و آماری هم نیست. عمداً ردیف‌هایی انتخاب می‌شوند که بیشترین اطلاعات فرایندی بدهند:
ردیف‌های پرکلید، وضعیت‌های متفاوت، کلیدهای تکرارشونده (fan-out)، ردیف ناقص برای آشکارشدن gap، و چند ردیف تصادفی برای کاهش سوگیری.

## هشدار

هیچ نتیجه‌ای در این pack «حقیقت کسب‌وکاری» نیست. grain، رابطه و تعارض همگی heuristic‌اند تا وقتی مالک منبع یا قرارداد تأییدشان کند. نبودِ شاهد هم اثبات انجام‌نشدن یک مرحله نیست.
