# AIBL V26.12.0 — ممیزی خصمانه نقاط تاریک معماری

چارچوب Chaos Engineering که فرستادید روی این کد **قابل استفاده بود، ولی
نه کلمه‌به‌کلمه**. اول تطبیقش دادم:

| بردار ممیزی | مصداق در AIBL |
|---|---|
| ۱ ناهماهنگی ماشین وضعیت | ✅ مصداق دارد — چرخه عمر قطعه و حالت‌های بی‌رویداد |
| ۲ شرایط رقابتی | ⚠️ نه در سطح ردیف (دیتابیس تراکنشی وجود ندارد) — ولی **در سطح فایل و اجرا مصداق کامل دارد** |
| ۳ حالت‌های مرزی محاسباتی | ✅ پربارترین بردار؛ سه یافته بحرانی |
| ۴ دور زدن اعتبارسنجی | ⚠️ محدود — تنها مسیرها `AIBL_STRICT_ADAPTERS` و بازنویسی گزارش رسمی‌اند که هر دو گاردشده‌اند |
| ۵ شکست نامتقارن تراکنش | ✅ مصداق دارد — مجموعه چندفایلی خروجی اتمیک نبود |
| ۶ نقاط کور مانیتورینگ | ✅ در ۲۶٫۱۱ تا حد زیادی بسته شد؛ اینجا تکمیل شد |

`WAREHOUSE_INVENTORY`، قفل خوش‌بینانه/بدبینانه، وب‌هوک و idempotency در
این سیستم موضوعیت ندارند: AIBL یک **خط لوله تحلیلی خواندنی روی فایل‌های
اکسل** است، نه یک سامانه تراکنشی. آن بخش‌ها را وانمود نکردم که پیدا
کرده‌ام.

## ۲) تحلیل عمیق شکست‌های بحرانی

### DC-01 — نماد علمی اکسل (Critical)

**سناریو گام‌به‌گام.** اکسل هر عدد بزرگ را خودکار `4.5E+09` می‌نویسد.
`num_safe` با `re.sub(r"[^\d.,]", "", s)` حرف `E` و علامت توان را دور
می‌ریخت:

```
"4.5E+09"  → "4.509"      ← تعهد ۴٫۵ میلیاردی، ۴٫۵ خوانده می‌شد
"1.23E+15" → "1.2315"
"1e-12"    → "112"
"2E5"      → "25"
```

**چرا خطرناک‌ترین بود:** خروجی **صفر نبود، یک عدد بود.** هیچ گارد
«داده ناقص» نمی‌گرفتش، در «جمع مانده تعهد» و در مخرج مقاومت می‌نشست، و
گزارش کاملاً سالم به نظر می‌رسید. ۹ مرتبه بزرگی خطا، بی‌صدا.

### DC-02 — هشدار ساختگی توقف خط (Critical)

**سناریو.** کاربری در ستون موجودی می‌نویسد `abc` یا سلول `inf` می‌شود:

```
num_safe("abc") = 0.0  و  is_empty_val("abc") = False
        ↓
موتور: «داده هست، مقدارش صفر است»
        ↓
total = 0 ⇒ BAND_STOCKOUT ⇒ 🔴 توقف خط
        ↓
هشدار اضطراری برای قطعه‌ای که ممکن است انبار پر باشد
```

**چرا خطرناک:** جهت خطا به سمت **اضطرارِ ساختگی** است. چند بار که چنین
هشداری بی‌مورد از آب دربیاید، دفعه بعد کسی به هشدار واقعی هم اعتماد
نمی‌کند.

### DC-06 — دو اجرای هم‌زمان (High)

**بازتولید واقعی روی همین ماشین:**

```
دو اجرای هم‌زمان روی یک پوشه خروجی
  → هر دو: «🏆 داشبورد ذخیره شد»
  → هر دو: کد خروج ۰
```

`os.replace` فایل را سالم نگه می‌دارد، ولی **مجموعه** مخلوط می‌شود:
گزارش از اجرای الف، دفتر سلامت از ب، فایل‌های کارشناس درهم. سناریوی
واقعی‌اش هم عجیب نیست: زمان‌بند ویندوز دیر اجرا می‌شود و کاربر هم دستی
اجرا می‌کند.

## ۳) پچ‌های معماری

### `num_parse()` کنار `num_safe()`

```python
num_parse(v) -> Optional[float]   # None یعنی «عدد نیست»
num_safe(v)  -> float             # صفر یعنی «عدد نیست» (سازگاری قبلی)
```

«داده نداریم» و «صفر است» دو چیزند و حالا دو خروجی دارند. موتور مقاومت
از `num_parse` استفاده می‌کند؛ بقیه کد دست‌نخورده با `num_safe` کار
می‌کند. نماد علمی **پیش از** هر پاک‌سازی دیگری تشخیص داده می‌شود.

### گارد وضعیت در موتور مقاومت

```python
if unreadable or not has_stock or not has_need:
    band = BAND_UNKNOWN          # نه STOCKOUT
...
days = round(min(max(total, 0.0) / need, self.max_days), 1)   # نه منفی
```

سلولی که هست ولی عدد نیست ⇒ ردیف به «نامشخص» می‌رود و **تعدادش در
«۱۷. سلامت سیستم» گزارش می‌شود** — تا کاهش ناگهانی «توقف خط» بی‌توضیح
نماند.

**آنچه عمداً تغییر نکرد:** توکن‌های `ندارد` / `N/A` طبق واژه‌نامه موجود
همچنان «تهی» شمرده می‌شوند. عوض کردنشان اعداد رسمی گزارش را جابه‌جا
می‌کند و آن تصمیم کسب‌وکار است، نه اثر جانبی یک ممیزی.

### `aibl/runlock.py` — قفل اجرا و نشانه مجموعه

```python
with RunLock(SETTINGS.OUTPUT_DIR):      # فقط در نقطه ورود CLI
    run()
```

* قفل **توصیه‌ای** با شناسه فرآیند؛ قفلِ بازمانده از فرآیند مرده خودکار
  نادیده گرفته می‌شود (بن‌بست نمی‌سازد).
* راه خروج صریح در متن خطا: `AIBL_FORCE_RUN=1`.
* `AIBL_Run_Complete.json` **بعد از** همه خروجی‌ها نوشته می‌شود و در شروع
  اجرای بعدی برداشته. نبودش یعنی مجموعه ناتمام است.
* قفل عمداً در `Pipeline.run` نیست تا فراخوانی کتابخانه‌ای و تست‌ها آزاد
  بمانند.

### بایگانی فایل کارشناس

فایل‌هایی که این نوبت ساخته نشدند به `_archive` منتقل می‌شوند — **حذف
نمی‌شوند**، چون پاک کردن داده کسی تصمیم ما نیست. و کد پرسنلی `nan` دیگر
به `nan__…` تبدیل نمی‌شود، بلکه `بدون_کد_پرسنلی__…` می‌شود.

### حالت‌های غیرقابل‌رسیدن، صریح

`UNOBSERVABLE_STAGES` اعلام می‌کند که `PR` و `SETTLEMENT` هیچ ستون تاریخی
ندارند، پس هیچ قطعه‌ای هرگز «معطل رفع تعهد ارزی» گزارش نمی‌شود — در حالی
که مدل ادعا می‌کرد این مرحله را پوشش می‌دهد. تست معماری، هر مرحله
بی‌رویدادِ **اعلام‌نشده** را قرمز می‌کند. رفع واقعی، افزودن ستون تاریخ به
سورس است — کار داده، نه کد.

## ۴) آزمون آشوب

`tests/test_chaos.py` — مجموعه چهاردهم، **۴۶ تست**. هر تست یک سناریوی
شکستِ **بازتولیدشده** است، نه فرضی:

| سناریو | آنچه سنجیده می‌شود |
|---|---|
| تزریق `4.5E+09` و `1e-12` | عدد درست، و نشکستن رفتار `1.234.567` و `(500)` |
| تزریق `abc` / `inf` / `NaN` در موجودی | «نامشخص»، **و** اینکه صفر واقعی همچنان توقف خط بدهد |
| موجودی منفی | مقاومت صفر، طبقه توقف خط |
| فایل زامبی + کد `nan` | بایگانی، نه حذف؛ نام صریح |
| قفل زنده / قفل مرده | رد اجرای دوم؛ عدم بن‌بست |
| نشانه مجموعه | ناتمام از کامل تفکیک شود |
| ترتیب معکوس + تاریخ آینده هم‌زمان | هر دو ثبت، وضعیت از تاریخ آینده ساخته نشود |
| ردیف کاملاً بی‌داده | بدون استثنا، بدون حدس |

**کل مجموعه: ۵۱۰ تست، ۰ ناموفق** (۲۶٫۱۱: ۴۶۴).

یک نکته: تستِ escape نامعتبر که در ۲۶٫۱۱ نوشته بودم، همین دور **رگرسیون
خودم** را گرفت — یک `\d` در docstring تازه. دقیقاً کاری که باید می‌کرد.
