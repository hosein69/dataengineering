# بررسی کد تازه و ریپوی پیشنهادی

## نتیجه کد تازه

ZIP کاربر GSI_29_7_7_RC2_CRITICAL_CASHFLOW.zip نسبت به RC1 هشت فایل برنامه/پیکربندی را تغییر داده و تست/مستند اضافه کرده است. ۱۲ تست همراه آن بدون تغییر پاس شدند. این نتیجه کافی برای پذیرش تولیدی نیست.

| شدت | یافته قابل بازتولید | تصمیم |

معماری چندشیتی SAP و کنترل شکست قرارداد شیت مفید و حفظ شد. ادعای «همهٔ هویت‌ها ساختاراً ناممکن است اشتباه شوند» از جدابودن شیت‌ها نتیجه نمی‌شود. داده با کلید خالی، تعارض تاریخ برابر و نبود سال سند هنوز نیازمند قرارداد کامل است.

## ارزیابی Continuous-Learning-AI-PoC

منبع: https://github.com/alipyth/Continuous-Learning-AI-PoC
شناسهٔ درخت کد بررسی‌شده در GitHub API: c5e3a79264afcffb5d42b8d50434d170f26ffa09
فایل‌های خوانده‌شده: readme.md و Continuous_Learning_Agents.ipynb (تمام سلول‌ها). دریافت از GitHub API؛ ابزار جست‌وجو قادر به واکشی صفحه نبود. هیچ API مدل فراخوانی و هیچ وابستگی آن نصب نشد.

حکم: الهام معماری برای ثبت بازخورد چت‌بات مفید است؛ ادغام مستقیم در این نسخهٔ GSI توصیه و انجام نشد.

- سه گره generator، validator و reflector با LangGraph؛ درس‌ها در agent_memory.json ذخیره و به پرامپت بعدی تزریق می‌شوند. این کار fine-tuning یا اصلاح وزن مدل نیست.
- validator برخلاف تعبیر کلی README، کد دلخواه را اجرا نمی‌کند؛ قطعهٔ لیست را با ast.literal_eval می‌خواند. سناریو فقط جمع 100/200 و ممنوعیت 50 را کنترل می‌کند.
- بازتولید مستقل: برای درخواست فهرست چهارتایی با مجموع 200، خروجی [200] نیز solved=True شد؛ طول فهرست کنترل نمی‌شود.
- حافظه فهرست جهانی رشته‌هاست: فقط برابری دقیق برای تکرار، بدون scope منبع/دامنه/نسخه/تاریخ مؤثر، حل تعارض، تأیید مالک، قفل یا نوشتن اتمیک. همهٔ درس‌ها هر بار وارد پرامپت می‌شوند.
- شکست یک تلاش مستقیماً به قاعده دائمی تبدیل می‌شود؛ این برای معنای ستون، تشخیص وضعیت یا فرمول مالی GSI قابل اتکا نیست.
- پروژه دو فایل آموزشی دارد؛ تست مستقل، قفل وابستگی یا ارزیابی روی دادهٔ GSI ندارد. badge README می‌گوید MIT اما فایل LICENSE در درخت بررسی‌شده نبود و metadata مجوز null بود؛ مجوز کپی کد احراز نشد. هیچ کدی کپی نشد.
- GSI از قبل lessons و knowledge_desk دارد؛ بنابراین افزودن LangGraph/OpenAI صرفاً برای ذخیره درس توجیه ندارد. در فاز جدا، پیشنهاد درس می‌تواند با شاهد، scope، تاریخ و تأیید مالک ذخیره شود؛ هیچ درس مدل نباید داده یا مرجع محاسبات را تغییر دهد.

محدودیت کاربر رعایت شد: هیچ کد این ریپو، مدل خارجی، سورس مالی تازه یا تغییر UI از این بررسی وارد بسته نشد.

## یافتهٔ تست سرتاسری پس از تطبیق

پچ تازه inbound را می‌خواند ولی raw_rows فقط PR/PO/pack را داشت؛ business_dwh از فریم‌های SAP غیر از raw_rows رابطه تولید نمی‌کرد. این یعنی ادعای پل SAP↔بارنامه در سطح adapter درست، اما تا DWH کامل نبود. افزودن شواهد خام و رابطهٔ مستقیم، با تست پایگاه داده تأیید شد.

همچنین نقشهٔ اعتبارات نشان داد مبلغ به یورو معادل پروفرماست. در دو مصرف‌کنندهٔ قدیمی رویداد نیز جایگزینی آن به‌عنوان مبلغ سوئیفت حذف شد. این اصلاح بدون مدل یادگیرنده و فقط بر مبنای هدر و نمونهٔ پیوست انجام شد.
