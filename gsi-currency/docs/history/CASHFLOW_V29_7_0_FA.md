# جریان وجوه و تعهدات چندارزی — Build 29.7.0

این نسخه موتور مالی مستقل و خروجی اختصاصی Excel و HTML را به GSI اضافه می‌کند. منطق نمای عملیاتی متریال تغییر نکرده است: NTSW و کارشناسان در آن نما همچنان نقش هشدار و کامنت دارند. در گزارش مالی، NTSW می‌تواند منبع شاهد تعهد/تخصیص باشد، اما مانده یا وضعیت آن پرداخت نقدی تلقی نمی‌شود.

## محل استفاده

در Dashboard بخش «گزارش اختصاصی جریان وجوه و تعهدات — Excel / HTML» و در Studio تب خروجی، همین بخش اضافه شده است. داده مالی بارگذاری‌شده در این دو مسیر فقط برای ثبت سفارش‌های محدوده فعلی محاسبه می‌شود. تغییر فیلتر، ورودی یا تاریخ، گزارش ذخیره‌شده قبلی را از نمایش خارج می‌کند.

برای کار بدون شبکه سازمان و بدون اجرای Pipeline:

```bash
streamlit run app/cashflow.py
```

این صفحه مستقل تمام محدوده فایل انتخابی را پردازش می‌کند. دفتر را بارگذاری کنید و دو خروجی اختصاصی را دریافت کنید. Excel کامل همان گزارش داخل HTML نیز قابل دریافت است؛ جست‌وجوی HTML برای نمایش است و فایل Excel تمام گزارش را دارد. در این نسخه Excel یک snapshot محاسبه‌شده است؛ تغییر مقادیر آن محاسبات Python را دوباره اجرا نمی‌کند. پس از اصلاح ورودی، گزارش را بازتولید کنید.

## قرارداد محاسبات

مبنای محاسبه `event_id` یکتا است، نه ردیف متریال/بارنامه حاصل join. مبالغ با Decimal محاسبه می‌شوند. هر ارز جدا باقی می‌ماند. ریال، تومان، دلار و یورو هرگز خودکار هم‌ارز فرض نمی‌شوند. نرخ را با واحد دقیق quote/base ثبت کنید؛ مثلاً IRR به ازای یک EUR. فایل باید شناسه‌های متنی و مبالغ افزایشی داشته باشد، نه snapshot مانده که هر روز تکرار شده است.

| خروجی | محاسبه و محدودیت |
|---|---|
| خالص گردش حساب | ورودی مستند − خروجی مستند، به تفکیک پرونده × حساب × ارز |
| مانده پایان حساب | مانده ابتدا + خالص گردش؛ بدون مانده ابتدا، نامشخص |
| جریان نقد ماهانه | تأمین/برگشت − پرداخت/کارمزد + ورودی تبدیل − خروجی تبدیل؛ انتقال داخلی دوباره شمرده نمی‌شود |
| مانده تخصیص | تخصیص مصوب − ابطال − مصرف ثبت‌شده؛ تخصیص جریان نقد نیست |
| مانده سهمیه | سهمیه مصوب − مصرف ثبت‌شده؛ نبود سهمیه، صفر نیست |
| مانده تعهد | تعهد ایجادشده − رفع تعهد مستند − عودت پذیرفته‌شده بانک |
| پرداخت فاقد منبع مرتبط | پرداخت − ارتباط‌های پذیرفته‌شده از منابع وجه |
| پرداخت فاقد بارنامه مرتبط | پرداخت − ارتباط‌های پذیرفته‌شده به حمل |
| مانده ارزش بارنامه بدون وجه | ارزش بارنامه − وجه مرتبط به ارز همان بارنامه |
| نرخ ضمنی تبدیل | مبلغ پای دریافتی ÷ مبلغ پای پرداختی |
| ارزش تاریخی | مبلغ × نرخ تأییدشده همان تاریخ/هدف/رژیم نرخ |
| ارزش پایان | مانده معلوم × نرخ معتبر تاریخ گزارش؛ جایگزین ارزش تاریخی نیست |

رفع تعهد با ترخیص، ارائه سند یا برگشت پول یکی نیست. `REFUND` گردش برگشت وجه است؛ فقط `COMMITMENT_RETURN` با سند پذیرش بانک تعهد را کاهش می‌دهد. ارزش گمرکی با نرخ `customs` و رفع تعهد با نرخ `settlement` ارزش‌گذاری می‌شود؛ نرخ حسابداری `accounting` جای آنها را نمی‌گیرد. اعلام تأیید در فایل، مسئولیت تهیه‌کننده دفتر است؛ موتور اصالت سند بانک را مستقل احراز نمی‌کند.

تبدیل معتبر دو پای هم‌پرونده، هم‌گروه، هم‌تاریخ و طرف تبدیل یکسان دارد. اگر یکی از پاها مفقود باشد، گردش مستند موجود حفظ می‌شود ولی نرخ تبدیل ساخته نمی‌شود و مغایرت اعلام می‌شود. ارتباط منبع به مصرف نقدی باید حساب و ارز یکسان داشته باشد؛ تغییر حساب یا ارز به رویداد مستقل انتقال/تبدیل نیاز دارد. تخصیص به بارنامه به‌صورت FIFO خودکار انجام نمی‌شود. روابط چندبه‌چند با مبلغ هر طرف و سند ارتباط ثبت می‌شوند. ارتباط بیش از ظرفیت از محاسبه کنار گذاشته و گزارش می‌شود؛ مبلغ اصلی تراکنش دست‌کاری نمی‌شود.

گزارش مانده‌ها فقط بر مبنای اسناد پذیرفته‌شده فایل است؛ به‌معنای کامل‌بودن دفاتر یا تأیید حسابرسی نیست. مبالغ منفی مانده به‌عنوان اضافه‌مصرف/مغایرت ظاهر می‌شوند و به صفر بریده نمی‌شوند. رویدادهای آتی یا فاقد مبلغ/ارز/سند لازم، در شواهد نیازمند تکمیل باقی می‌مانند.

## ورودی‌ها

ساخت قالب‌های CSV:

```bash
python -m gsi.cashflow --templates --out cashflow_templates
```

فایل Excel ورودی می‌تواند شیت‌های `Events`, `Links`, `Rates`, `Rules` داشته باشد. CSV رویدادها هم پذیرفته می‌شود؛ Links و Rates را می‌توان جدا در پنل بارگذاری کرد. فایل Events.csv را هنگام ویرایش در Excel با ستون‌های شناسه از نوع Text وارد کنید تا شناسه بلند از بین نرود.

### Events

- `event_id`: شناسه پایدار و یکتا؛ تکرار دقیق یک بار محاسبه می‌شود؛ تناقض با همان شناسه تمام نسخه‌ها را از محاسبه خارج می‌کند.
- `case_id`: شناسه پرونده/ثبت سفارش؛ `order_id`, `bl_id`: فقط رابطه مستند، نه حدس از کارشناس.
- `kind`: یکی از انواع جدول زیر؛ `date`: تاریخ رویداد، شمسی یا میلادی. خروجی تاریخ میلادی دارد.
- `amount`, `currency`: مبلغ افزایشی و کد ارز. منفی و عدد نامتناهی پذیرفته نمی‌شود.
- `from_account`, `to_account`: حساب مبدأ/مقصد. حساب‌های متعلق به محدوده گزارش با `OWN:` شروع می‌شوند؛ مانند `OWN:BankA:EUR`؛ طرف‌های بیرونی مانند `EXTERNAL:SupplierA`.
- `source`, `document`: منبع و مرجع سند. `status=POSTED` فقط برای رکورد تأییدشده توسط تهیه‌کننده دفتر؛ `OBSERVED` برای شواهد ناقص.
- `group_id`: گروه دو پای تبدیل ارز؛ `rate_regime`: نام رژیم نرخ دقیقاً مطابق Rates.
- `due_date`, `rule_id`: مهلت اعلامی و شناسه قاعده؛ `note`: توضیح.

| نوع | معنی |
|---|---|
| OPENING | مانده ابتدا؛ از حساب خارج محدوده به OWN؛ یک مانده اولیه یکتا برای هر پرونده/حساب/ارز |
| FUNDING, PAYMENT, REFUND, FEE | تأمین وجه، پرداخت، برگشت وجه، کارمزد؛ گردش واقعی |
| FX_SELL, FX_BUY | دو پای تبدیل ارز، هر کدام به ارز اصلی خود |
| TRANSFER | انتقال میان دو حساب OWN؛ در خالص کل پول دوباره شمرده نمی‌شود |
| FILE, REGISTRATION, QUEUE | ایجاد پرونده، ثبت سفارش، درخواست/صف تخصیص |
| ALLOCATION, ALLOCATION_CANCEL, ALLOCATION_USE | تصویب، ابطال و مصرف تخصیص؛ بدون گردش نقد |
| QUOTA, QUOTA_USE | مبنای سهمیه و مصرف آن؛ بدون گردش نقد |
| COMMITMENT, SETTLEMENT, COMMITMENT_RETURN | ایجاد تعهد، رفع تعهد و عودت پذیرفته‌شده بانک |
| SHIPMENT, CUSTOMS, CLEARANCE, WAREHOUSE, BANK_DOCS | شواهد حمل، اظهار، ترخیص، انبار و ارائه اسناد بانک |

### Links

`link_id`, `from_event`, `to_event`, `from_amount`, `to_amount`, `document`, `authorization`.
مبلغ مبدأ به ارز رویداد مبدأ و مبلغ مقصد به ارز رویداد مقصد است. برای تخصیص میان پرونده‌ها مرجع مجوز لازم است. ارتباط یک پرداخت به حمل، گمرک و رفع تعهد، سه تطبیق مستقل است؛ سه پرداخت محسوب نمی‌شود. ارتباط اثبات‌نشده پول را جابه‌جا نمی‌کند.

### Rates

`date`, `base`, `quote`, `rate`, `purpose`, `source`, `approved`, `max_age_days`, `regime`.
`rate` تعداد واحد quote به ازای یک base است. نرخ باید مثبت، منبع‌دار و `approved=true` باشد. فقط نرخ همان تاریخ یا قبل از آن در حد `max_age_days` مجاز است؛ نرخ آینده استفاده نمی‌شود. آخرین تاریخ معتبر با دو نرخ متفاوت، مغایرت است. تبدیل معکوس/مثلثی خودکار انجام نمی‌شود. برای تاریخ گزارش و هدف/رژیم موردنظر، نرخ جدا لازم است. برای IRT و IRR نرخ صریح بدهید؛ موتور واحد ورودی را حدس نمی‌زند.

### Rules

`rule_id`, `kind`, `source`, `effective_from`, `effective_to`, `approved`.
قاعده فقط در بازه معتبر، با منبع و تأیید ورودی به مهلت اعلامی برچسب می‌زند. این نسخه از قواعد، جریمه یا مهلت حقوقی خودکار تولید نمی‌کند. انقضای قاعده به‌معنای تمدید آن نیست. ثبت شماره بخشنامه به‌تنهایی اصالت و اعتبار روز آن را اثبات نمی‌کند.
