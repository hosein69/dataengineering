# GSI V28.5 — بهینه‌سازی HTML مستقل

## مسئله
HTMLهای داینامیک در نسخه‌های قبل برای هر ردیف نام تمام ستون‌ها را دوباره در JSON تکرار می‌کردند و بخش بزرگی از `process_extras` را نیز دوباره در JavaScript قرار می‌دادند؛ در حالی‌که Process/Kanban جدید قبلاً در همان تب به HTML تبدیل شده بود.

## اصلاحات
- payload اصلی از `record objects` به `row arrays + COL_INDEX` تبدیل شد. هیچ ردیف یا فیلدی حذف نمی‌شود.
- Runtime همچنان از `S(row, column)` استفاده می‌کند و با payload جدید/قدیمی سازگار است.
- Event Log، Action Queue، FX ledger و جداول حجیم Process دیگر بدون نیاز دوباره داخل `PROC` embed نمی‌شوند.
- فقط داده کوچک مورد نیاز Story یا نمودار Bottleneck در runtime نگه داشته می‌شود، آن هم با ستون‌های allowlist.
- Process Mining، Kanban، Case Timeline، جدول، فیلتر و Excel فیلترشده حفظ شده‌اند.
- Studio بعد از ساخت، اندازه واقعی HTML را نمایش می‌دهد و اگر از 8MB بالاتر باشد هشدار می‌دهد.

## اندازه‌گیری QA
روی دیتاست شبیه اجرای واقعی با 7,400 ردیف، داده عریض، 7,800 Event و 5,400 Action:
- قبل: 9.31 MB
- بعد: 2.77 MB
- کاهش: 70.3%

این عدد نمونه QA است و اندازه واقعی به تعداد فیلدها/ردیف‌ها و Viewهای انتخابی هر تب بستگی دارد.

## قرارداد
- Missing هرگز Zero نمی‌شود.
- Scope قبل از embed شدن اعمال می‌شود.
- کاهش حجم نباید باعث truncation پنهانی ردیف‌ها شود.
- `payload_rows` همچنان تعداد ردیف‌های دامنه گزارش را اعلام می‌کند و `embedded_rows` تعداد ردیف واقعاً embed شده را نشان می‌دهد.
