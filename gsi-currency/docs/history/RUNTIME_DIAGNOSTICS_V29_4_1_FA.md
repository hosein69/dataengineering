# V29.4.1 — تشخیص زمینه‌محور خطا و همزمانی

این Hotfix پیام گمراه‌کننده‌ی «اجرای دیگری فعال است → gsi.doctor را بزنید» را اصلاح می‌کند.

## اصل
قفل نویسنده‌ی DWH یک **کنترل همزمانی** است، نه خطای سورس. وجود فایل lock نیز به‌تنهایی نشانه‌ی اجرای فعال نیست؛ فقط OS advisory lock منبع حقیقت است.

## تغییرها
- خطای اختصاصی `WAREHOUSE_WRITER_BUSY / CONCURRENCY` با metadata شامل host، pid، run_id، زمان و operation.
- تشخیص `SELF_REENTRY` در برابر `CONCURRENT_WRITER`.
- پیشنهاد `gsi.doctor` فقط برای خطاهای مسیر/محیط؛ نه برای قفل نویسنده.
- در زمان اجرای همزمان، UI در صورت وجود Snapshot سالم قبلی همان را با برچسب واضح `UPDATE_IN_PROGRESS / stale_snapshot` نشان می‌دهد و صفحه از کار نمی‌افتد.
- `gsi.doctor` وضعیت واقعی writer lock را probe می‌کند و lock-file کهنه را با writer فعال اشتباه نمی‌گیرد.
- جزئیات تشخیصی به‌صورت code/category/impact/action نمایش داده می‌شود تا دوباره‌کاری کم شود.

## نکته عملی
اگر پیام `WAREHOUSE_WRITER_BUSY` دیده شد، حذف دستی فایل `.writer.lock` توصیه نمی‌شود. اگر OS lock آزاد باشد، فایل باقی‌مانده مانع اجرا نیست. اگر OS lock واقعاً فعال باشد، اجرای دوم باید منتظر اجرای مالک بماند.
