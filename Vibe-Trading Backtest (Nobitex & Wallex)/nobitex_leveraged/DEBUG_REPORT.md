## F1 — باگ بحرانی: پنجره‌ی زمانی بی‌صدا کوتاه می‌شود

### علت

```python
params = {"symbol": ..., "resolution": ..., "from": start, "to": now}
r = requests.get(NOBITEX, params=params, timeout=30)
```

یک درخواست، بدون `page` و بدون تکه‌کردن پنجره. ولی endpoint نوبیتکس در هر پاسخ حداکثر **۵۰۰ کندل** می‌دهد. پس هر پنجره‌ای که بیش از ۵۰۰ کندل بخواهد، به جدیدترین ۵۰۰ کندل بریده می‌شود — **بدون هیچ خطا یا هشداری**.

و چون تنها محافظ موجود این است:

```python
if n < 200:
    raise RuntimeError(f"{symbol}: only {n} bars returned; refusing unstable test")
```

عدد ۵۰۰ از ۲۰۰ بزرگ‌تر است، پس تست «قبول» می‌شود و نتیجه‌ی یک پنجره‌ی ۵ روزه به‌عنوان مطالعه‌ی ۳۰ روزه (یا ۱۸۰ روزه) گزارش می‌شود.

### بازتولید

```
درخواست: --lookback-days 30 --resolution 15
انتظار : 2880 کندل
تحویل  : 500 کندل
پوشش   : 17.4٪
پنجره‌ی واقعی: 5.20 روز
```

جدول کاملِ اینکه هر تنظیمی واقعاً چند روز می‌گیرد:

| resolution | ۳۰ روز یعنی چند کندل | واقعاً چه می‌گیرید | نتیجه |
|---|---:|---:|---|
| 15m | 2880 | 500 (۵.۲ روز) | بی‌صدا غلط |
| 30m | 1440 | 500 (۱۰.۴ روز) | بی‌صدا غلط |
| 60m | 720 | 500 (۲۰.۸ روز) | بی‌صدا غلط |
| 240m | 180 | 180 | با خطای «کمتر از ۲۰۰ کندل» رد می‌شود |
| D | 30 | 30 | با خطای «کمتر از ۲۰۰ کندل» رد می‌شود |

یعنی با کد اصلی، **هیچ تنظیمی وجود ندارد که یک ماه داده‌ی درست بدهد**: یا بی‌صدا کوتاه می‌شود، یا اجرا را رد می‌کند.

### اصلاح

پنجره با درخواست‌های متوالیِ زیر سقف پوشش داده می‌شود:

```python
chunk_seconds = (MAX_PER_REQUEST - 1) * step     # هر تکه زیر ۵۰۰ کندل
cursor = start
while cursor < now:
    chunk_end = min(cursor + chunk_seconds, now)
    payload = _request_page(symbol, resolution, cursor, chunk_end, 1)
    ...
    cursor = max(newest + step, chunk_end)       # محافظ در برابر گیر کردن
```

تکه‌کردن پنجره به‌جای پارامتر `page` انتخاب شد چون به سمانتیک سرور وابسته نیست: هر تکه یک درخواست بازه‌ای مستقل و خوداعتبارسنج است. (در تست محلی با یک mock که عمداً `page` را نادیده می‌گرفت، نسخه‌ی مبتنی بر `page` شصت درخواست می‌فرستاد و هیچ پیشرفتی نمی‌کرد — دلیل اضافه‌شدن محافظ گیرکردن.)

به‌علاوه یک ممیزی پوشش روی خود فریم ثبت می‌شود و اگر تحویل به‌طور محسوس کمتر از درخواست باشد، اجرا **با خطا رد می‌شود** نه اینکه نمره بگیرد:

```python
if coverage["coverage_ratio"] < args.min_coverage:      # پیش‌فرض ۰.۸
    raise RuntimeError(f"... refusing to grade a {span}-day sample as {days} days")
```

نتیجه‌ی تست بعد از اصلاح:

```
requested_days 30 | expected_bars 2880 | delivered_bars 2880
coverage_ratio 1.0 | pages_walked 6 | actual_span_days 29.99
```

## F2 — باگ بحرانی: کارمزد ورود دو بار کسر می‌شود

هنگام باز کردن پوزیشن:

```python
equity -= entry_fee                      # خط ۳۲۵ نسخه‌ی اصلی
```

و هنگام بستن:

```python
net = pnl - pos.entry_fee - extension_fee - exit_fee
new_equity = equity + net                # entry_fee دوباره کسر می‌شود
```

`equity` قبلاً کارمزد ورود را از دست داده بود، پس `- pos.entry_fee` دوم آن را دوباره کم می‌کند.

### بازتولید

پوزیشنی با قیمت ورود و خروج **یکسان** (سود ناخالص صفر)، کارمزد ورود ۲۵:

```
سود ناخالص      : 0.00
equity درست      : 99,972.50      (= 100,000 − 25 ورود − 2.5 خروج)
equity نسخه‌ی اصلی: 99,947.50
خطا              : دقیقاً 25.00 = یک entry_fee کامل
```

### اصلاح

تفکیک صریح «آنچه هنوز باید اعمال شود» از «اقتصاد کامل رفت‌وبرگشت»:

```python
still_owed     = pnl - extension_fee - exit_fee   # به equity اعمال می‌شود
round_trip_net = still_owed - pos.entry_fee       # در دفتر گزارش می‌شود
new_equity     = equity + still_owed
```

حالا `equity` درست است و `net_pnl` دفتر هم همچنان هزینه‌ی کامل رفت‌وبرگشت را نشان می‌دهد.

## F3 — پرشدن لیکوییدیشن روی بدترین قیمت کندل

نسخه‌ی اصلی:

```python
return bar["low"] <= breach_price, max(float(bar["low"]), 0.0)   # لانگ
```

یعنی **شرط فعال‌شدن** قیمت breach است ولی **قیمت پرشدن** کف کندل. اگر کف کندل خیلی پایین‌تر از breach باشد، ضرر به‌شدت بزرگ‌تر از واقعیت ثبت می‌شود. این «محافظه‌کاری» نیست؛ فرض می‌کند همیشه بدترین تیک کل کندل نصیب شما می‌شود.

فرمول خود breach درست است و بررسی شد:

```
لانگ : collateral + qty·(P − entry) ≤ threshold  ⟹  P ≤ entry + (threshold − collateral)/qty  ✓
شورت: collateral + qty·(entry − P) ≤ threshold  ⟹  P ≥ entry + (collateral − threshold)/qty  ✓
```

### اصلاح

پرشدن روی خود قیمت breach، مگر اینکه کندل با گپ از آن رد شده باشد که در آن صورت اولین قیمت در دسترس، `open` است؛ سپس اسلیپیج نامساعد:

```python
fill = min(breach, float(bar["open"]))        # لانگ: محافظت در برابر گپ
return True, max(fill * (1.0 - slippage), 0.0)
```

## F4 — متریک‌های محاسبه‌شده دور ریخته می‌شوند

`run_symbol` یک دیکشنری کامل می‌سازد (`sharpe`, `sortino`, `calmar`, `cagr`, `profit_factor`, `median_trade_return`, `liquidations`) و بعد:

```python
return eq.reset_index(), tr        # metrics هرگز برنمی‌گردد
```

سپس `main` زیرمجموعه‌ای از آن‌ها را **با فرمول متفاوت** دوباره حساب می‌کند، و این هم در مسیرش هست:

```python
**{k: (...) for k, v in run_symbol.__annotations__.items() if False},
```

`if False` یعنی این عبارت همیشه `{}` است — کد مرده‌ای که فقط خواننده را گمراه می‌کند.

### اصلاح

محاسبه در یک تابع `compute_metrics` متمرکز شد، `run_symbol` سه‌تایی `(eq, trades, metrics)` برمی‌گرداند، و `main` همان را مصرف می‌کند. حالا sortino و calmar و cagr و profit_factor واقعاً در JSON خروجی هستند.

## F5 تا F8 — باگ‌های کوچک‌تر

**F5.** `run_symbol` بازده را با `.replace([inf,-inf], nan).fillna(0)` پاک می‌کرد ولی `main` فقط `.fillna(0.0)` می‌زد. چون منحنی equity با `max(mark, 0.0)` در صفر کلیپ می‌شود، `pct_change` از صفر مقدار نامتناهی می‌دهد و شارپِ `main` خراب می‌شود. حالا هر دو از یک تابع `equity_returns` استفاده می‌کنند.

**F6.** `downside = rets.clip(upper=0)` همه‌ی کندل‌های بی‌حرکت را صفر می‌کند و در انحراف معیار نگه می‌دارد، که downside vol را کم و sortino را زیاد نشان می‌دهد. اصلاح: `rets[rets < 0]`.

**F7.** `for i in range(31, len(df) - 1)` — عدد ۳۱ نه به span=30 ربط دارد (یک EMA که روی اولین مشاهده بذر می‌گیرد تقریباً ۳ برابر span لازم دارد تا بذر را فراموش کند) و نه به پنجره‌ی ATR. اصلاح: `warmup_bars(slow, atr_n, slope_lag) = max(3·slow, atr_n+1, slope_lag+1)` که برای پیش‌فرض‌ها ۹۰ کندل می‌شود، به‌علاوه‌ی خطای صریح اگر نمونه کوتاه‌تر از warm-up باشد.

**F8.** خروج `SIGNAL_FLIP` روی `next_row["open"]` پر می‌شود ولی با `ts` (کندل جاری) مهر می‌خورد. حالا با `next_row.name` مهر می‌خورد تا دفتر با قیمت پرشدن سازگار باشد.

**کد مرده‌ی حذف‌شده:** `equity_mark` (محاسبه می‌شد و هرگز خوانده نمی‌شد)، `last_ts`، ستون‌های `ret` و `vol20` (هرگز استفاده نشدند)، و همان `if False`.

## آنچه اصلاح نشد و عمداً باقی ماند

- **پروکسی بودن لیکوییدیشن.** همان‌طور که نویسنده‌ی اصلی درست نوشته بود، این بازسازی موتور ریسک نوبیتکس نیست. فقط قیمت پرشدنش واقعی‌تر شد.
- **`max_leverage_from_market_info` که فقط ورودی را برمی‌گرداند.** بدون احراز هویت نمی‌شود سقف اهرم هر بازار را از نوبیتکس گرفت؛ رفتار فعلی صادقانه است و در خروجی هم به‌عنوان «درخواستی» برچسب خورده.
- **`maintenance_ratio = 0.50`.** فرض تهاجمی است (لیکویید وقتی نصف وثیقه رفته)، ولی یک انتخاب پیکربندی است نه باگ.
- **کارمزدها.** `fee_rate=0.0025` و `extension_fee_daily=0.001` فرض‌اند، نه جدول رسمی.
